# Player modes and name-based local saves

- **开发模式**: opens the existing development progression (`user://progression.cfg`) with the current wallet/upgrades preserved and all three missions plus Endless available. This is normal gameplay with the current state, separate from **LAB / 调参**, which retains historical tuning/telemetry behavior and baseline stats.
- **游客模式**: starts at 0 G, no purchased upgrades and only mission one unlocked. Guest progress is memory-only. Returning to the title and choosing **继续游客游戏** retains that same visit's currency/upgrades/unlocks so the build tree remains usable. **新游客 / 从零开始**, switching back to development and entering Guest again, or restarting the app creates another fresh visit.
- **名字存档**: enter a name and use **读取存档** (or Enter in the field). A new name starts at 0 G, no upgrades, mission one only; an existing name restores that name's wallet, purchases, unlocks and high scores. It uses the same local machine; no server/account service is involved. Names trim surrounding whitespace, accept up to 32 characters and match case-insensitively. A SHA-256-derived filename prevents names from becoming filesystem paths.

Guest and named players unlock mission 02 by clearing mission 01's Boss, mission 03 by clearing mission 02, and Endless by clearing mission 03. Disabled mission rows explain the requirement; the start API also checks the lock. Replay/retry does not erase the current visit/profile. Named progression saves on coins/purchases/unlocks/records under `user://profiles/<name-hash>.cfg`, without the development profile's 600 G grant. Guest scores never write to the existing shared high-score file. An unreadable name file is not overwritten and leaves the current profile selected.

The background real-game demo continues in its own memory-only instance and does not use any of these live player profiles. Settings remain shared local presentation/audio settings.

Verification: player_profiles_smoke verifies Guest reset/continuation, sequential unlocks, API lock enforcement, development isolation, fresh named state, blank-name rejection, case-insensitive IDs and a named save roundtrip confined to `res://tmp`. Existing start_modes, campaign_modes, progression and settings checks passed; some checks still have exit-only ObjectDB cleanup warnings. Real-render captures checked the upper-right menu, locked selector, empty tree and named selector. No user save or historical telemetry was modified by tests.

UI flow: mode/name entry -> mission selector -> Build Upgrade or mission. The selector prominently shows the active wallet and build entry; leaving the tree returns to the same selector/profile. The initial title page no longer shows upgrades or a wallet.
